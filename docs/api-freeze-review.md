# Public API freeze review (issue #30)

Status at 0.21.0, written for the freeze at 1.0.0-rc.1. The public surface is every type tagged `@api`; the full signature
list is [api-surface.md](api-surface.md), regenerated by `php scripts/api-surface.php > docs/api-surface.md`.
`tests/Unit/ApiSurfaceTest.php` fails when that file is stale, so every API change shows up as a diff in review, and
`tests/Unit/ApiTagsTest.php` fails when a type under `src/` is neither `@api` nor `@internal`. A public method tagged
`@internal` in its own docblock is left out of the surface file and is outside the semver promise like an `@internal` class.
(The `roave/backward-compatibility-check` job runs in CI only; it needs PHP 8.4.)

## What is settled

- **Contracts** (`Database`, `Contracts`, `Redis\RedisClientProviderInterface`, `Webhooks\*Interface`, `ITSM\TicketProblemLinkInterface`,
  `Mcp\AgentDirectoryInterface`, `Compliance\*Interface`): small, edition-implemented, already used by two editions. Frozen as is.
- **Errors:** see [Error behaviour](#error-behaviour).
- **Tables and columns:** only additive migrations (0001 to 0013), each idempotent and recorded in `rivet_core_migrations`; see
  [Tables and columns (frozen)](#tables-and-columns-frozen).
- **Array shapes:** the global PHPStan ignore for `missingType.iterableValue` is gone. Every public and private `array` parameter and
  return now carries an `array<...>` / `list<...>` / array-shape docblock (open shapes use `array<string,mixed>`). The only
  remaining baseline is `phpstan-baseline-converters.neon`, for `DocxConverter` and `PdfConverter` redundant-check findings.
- **Long constructors:** `RedisConnectionConfig` (10 parameters), `WebhookDispatcher` (8) and `ToolPipeline` (7) are frozen with
  **named arguments as the supported calling style**, stated in each class docblock and covered by `tests/Unit/NamedArgumentsTest.php`.
  Positional order is kept for existing callers and new options are only ever appended. No options object is introduced.
- **Logger:** the `\Closure|LoggerInterface|null` union on `UnlinkedIdentityStore`, `IdentityLinker` and `ToolPipeline` stays, with the
  Closure form marked `@deprecated` (works through all of 1.x, removed in 2.0). Editions should pass a PSR-3 logger.
  `ErrorLogLogger::resolve()` is unchanged (it was already `@internal`).
- **Webhook signatures:** `X-Rivet-Signature-V2` (with `X-Rivet-Timestamp`) is the documented default. The legacy `<prefix>-Signature`
  header is `@deprecated` in the `WebhookDispatcher` docs, kept through all of 1.x, and removed no earlier than 2.0.

## Surface narrowed in this review

Public methods whose only purpose is internal plumbing or tests were tagged `@internal` (still callable, no longer promised; absent
from `api-surface.md`):

| Method | Reason |
|---|---|
| `Webhooks\WebhookDispatcher::curlOptions()`, `::pinnedUrl()` | public only so tests can assert connection pinning without a network call |
| `Webhooks\EventSummary::clean()`, `::clip()`, `::isSafeUrl()` | formatter helpers; no edition calls them |
| `Compliance\ReportRenderer::csvCell()` | rendering helper (used through a callable inside the class) |
| `Compliance\ComplianceAssessor::summarize()` | called by `assess()` only |
| `Compliance\Nist171Map::apply()` | called by the assessor and client checklist only |
| `Mcp\ToolPipeline::envelope()` | called by `run()` only |
| `Support\ErrorLogLogger::resolve()` | already `@internal` before; now also absent from the surface file |

Data constants (`Nist171Map::MAP`, `ChangeService::TRANSITIONS`, `Framework::LABELS`, ...) stay public: editions read them for
validation and display. No setter exists only for tests.

One addition: `Migration\MigrationInProgressException` (`@api`, extends `\RuntimeException`) replaces the raw `\RuntimeException`
thrown by `MigrationRunner::run()` when another runner holds the lock, so existing `catch (\RuntimeException)` code keeps working.

## Error behaviour

Rules that hold across Core:

1. **Storage failures** surface as `Database\DatabaseException` (a `\RuntimeException`), thrown by the `DatabaseInterface`
   implementation. Core code never touches `\mysqli` directly, so no raw driver exception escapes from a Core method; editions
   implementing `DatabaseInterface` must wrap driver errors (the `DatabaseContractTestCase` suite checks this).
2. **Caller mistakes** (unknown id, invalid status transition, bad input) throw `\InvalidArgumentException` with a message that is safe
   to show an administrator. This is a deliberate, documented choice, not a Core exception class per module.
3. **Best-effort side effects** never throw to the caller: webhook delivery, audit fan-out, the unlinked-identity store, MCP audit
   rows, log writes.
4. **Redis is optional:** every Redis-backed service fails open (returns "allowed" / "acquired" / `null` / a default) when Redis is
   absent or erroring; none throws.

| Class::method | Throws | Returns on failure |
|---|---|---|
| `Audit\AuditService::log` | `DatabaseException` if the insert fails; nothing from `afterLog` (swallowed); unencodable metadata is replaced by `{"_error":...}` | `void` |
| `Audit\AuditReader::*` | `DatabaseException` | invalid stored metadata JSON decodes to `null` |
| `Retention\RetentionService::prune/plan` | `DatabaseException` | a table with no horizon is skipped (empty result) |
| `Migration\MigrationRunner::run` | `MigrationInProgressException` when another runner holds the lock past the wait; `DatabaseException` from a failing migration (earlier migrations stay recorded); `\InvalidArgumentException` from the constructor on duplicate ids | applied ids (empty list when current) |
| `Migration\MigrationRunner::status/pending` | none for a missing table | table missing counts as nothing applied |
| `Jobs\JobQueue::*` | `DatabaseException` | `markCompleted`, `markFailed`, `release`, `retry` return `false` when the job is no longer in the expected state |
| `Jobs\JobWorker::runOne/run` | none from handlers: `PermanentJobFailure` dead-letters at once, any other `\Throwable` (incl. `JobTimeout`) is recorded and retried until `max_attempts`; `DatabaseException` from the queue itself | counters array |
| `Cron\JobRunner::start/status` | none | `['ok'=>false,'message'=>...]` for an unknown script or a start failure |
| `Cron\JobCatalog::describe` | none | a generic "unrecognized job" entry |
| `Webhooks\WebhookDispatcher::deliver/deliverTo` | never throws (documented) | result row with `ok:false` and an `error` string; a rejected URL is not contacted |
| `Webhooks\PayloadFormatter::format`, `PayloadTemplate::render` | `\InvalidArgumentException` (unknown format, missing option, invalid or oversized template) | n/a |
| `Webhooks\Authentication::headers` | `\InvalidArgumentException` on an invalid config | `[]` for mode `none` |
| `Webhooks\UrlPolicy::isSafe/vet` | none (resolver errors count as unsafe) | `false` / `null` |
| `Automation\AutomationRuleStore::save` | `\InvalidArgumentException` (message safe to show); `DatabaseException` | n/a |
| `Automation\AutomationExecutor::execute` | never throws: handler exceptions are caught | `['ok'=>false,'message'=>...]` (500 chars max) |
| `Compliance\ComplianceAssessor::assess` | never throws for a failing check | that check becomes `Status::Error` with a fixed message (no exception text leaks) |
| `Compliance\AttestationStore::record`, `SubjectCompliance::*`, `SharedReport::*`, `ResponsibilityStore::*` | `\InvalidArgumentException` for unknown item, bad date, missing reviewer or missing snapshot; `DatabaseException` | `null` for a missing snapshot on read methods |
| `ITSM\ProblemService`, `ITSM\ChangeService` | `\InvalidArgumentException` for unknown id, invalid status/risk or an illegal transition; `DatabaseException` | n/a |
| `Workflow\WorkflowService::startRun` | `\InvalidArgumentException` for an unknown template; `DatabaseException` | task methods on unknown ids change nothing |
| `Mcp\ToolPipeline::run` | never throws: `NotFoundException` from a tool body becomes a `NOT_FOUND` envelope, any other `\Throwable` an `INTERNAL_ERROR` envelope without the message; a throwing `$allow` is a `PERMISSION_DENIED` envelope (fail closed); a rate-limited caller gets `RATE_LIMITED`; audit failures are logged only | envelope with `success:false` |
| `Mcp\IdentityLinker::link` | none: failures are logged and the transaction rolled back | `[false, message]` |
| `Mcp\UnlinkedIdentityStore::record` | never throws (must not change the 403) | `void`; other methods throw `DatabaseException` |
| `Mcp\McpDiagnostics::run` | none: every probe failure becomes a `fail`/`warn` check row | check rows |
| `Mcp\RedisMetadataCache::*` | none | the default / `false` |
| `Redis\RateLimiter::hit` | none | `allowed:true` (fail open) |
| `Redis\LockManager::acquire/run`, `Lock::extend/release`, `CronGuard::acquire` | none | degraded lock that reports as held; `extend` returns `false` on error; `CronGuard::acquire` returns `null` when another copy holds the lock |
| `Redis\RedisAdmin::test/setMemory` | none for connection or command errors | `['ok'=>false,'message'=>...,'reason'=>...]` with the password redacted |
| `Redis\RedisAdmin::stats/groupCounts/clear` | the caller-supplied Predis client's exceptions propagate (the caller already holds a working connection); `clear` throws `\InvalidArgumentException` for a group that is not allowlisted | n/a |
| `Health\ReadinessChecker::check` | none | `database: fail`, `redis: unavailable` |
| `KB\DocxConverter::convert`, `KB\PdfConverter::convert` | `DocxConversionException` / `PdfConversionException` (message safe to show) for anything malformed, oversized, encrypted or when the tools are missing | n/a |
| `Contracts\AccessDenied::unless` | `AccessDenied` when the policy says no | `void` |
| `Compliance\CheckInterface::run` (edition-implemented) | must not throw; the assessor guards it anyway | a `CheckResult` |

Inconsistencies found and fixed: `MigrationRunner::run()` threw a bare `\RuntimeException` for the lock timeout (now
`MigrationInProgressException`, still a `\RuntimeException`). No public Core method throws a raw `\mysqli_sql_exception`: Core has
no direct `\mysqli` use. `McpDiagnostics` still uses `\RuntimeException` internally, but only inside private methods whose
exceptions are caught and turned into check rows.

## Tables and columns (frozen)

All tables are created `IF NOT EXISTS` (InnoDB, utf8mb4, `utf8mb4_general_ci`). From 1.0 columns are only added, never renamed, retyped
or dropped; a column that must go is deprecated in documentation first. **Public** means editions may read the table directly (for
reports and admin pages) and rely on the columns; writes still go through the Core service. **Internal** tables are for Core services
only: editions use the service API and must not depend on the layout.

The `_json` columns hold JSON text whose keys are additive-only. The compliance JSON documents (`summary_json`, `results_json`) are read
only through `SnapshotStore`/`Assessment::fromArray`, which tolerate missing keys.

Index review: `audit_events`, `webhook_deliveries` and `integration_jobs` are pruned with `created_at < ?` and the audit date filters
read `created_at`, but none had an index that started with `created_at` (the existing ones lead with another column, so they could not
serve a range scan). Migration `0013_retention_indexes` (`Retention\Migration\Migration0013RetentionIndexes`) adds
`idx_audit_events_created`, `idx_webhook_deliveries_created` and `idx_integration_jobs_status_created`; each is created only when
`information_schema.STATISTICS` shows it missing. Other gaps noted and left alone (not on a hot path): `workflow_runs` has no index on
`status`, `compliance_attestations` has none on `reviewed_on`, and the `*_id` columns (`webhook_id`, `contact_id`, ...) are plain
integers without foreign keys on purpose, because the referenced tables belong to the editions.

## Still open before 1.0.0

1. **`@internal` test helpers.** `Testing\DatabaseContractTestCase` and the conformance base classes extend PHPUnit and are used by both
   editions' suites. Decision #49 (separate dev package or keep) must land before 1.0 because they are outside the BC promise today.
2. **Access policy.** `AccessPolicyInterface` (ADR-003) ships but no service enforces it yet. First adopters: Automation execution and
   MCP tool calls; freeze after one real adopter in each edition.
3. **Namespaces.** The edition shims under `ITFlow\` stay for 1.x (decision #45 recommended: yes, deprecated, not removed).
