# Core security audit (rc.42 + later), 2026-10

Status: in progress, written incrementally. No raw secret value appears in this document: a value is referred to by file:line, type, length and the first 4 hex characters of its SHA-256 (fp).

## 1. Scope and method

- Repository: rivet-core, branch `core-audit` from origin/main (v1.0.0-rc.42 plus later commits). Editions are read only.
- Scratch environment (Docker, random passwords, removed afterwards): MariaDB 10.11, PostgreSQL 18, Redis 7 plain, with auth and with TLS, php 8.5 image with pdo_pgsql, golang:1.27.
- Own scanner `scripts/secret-scan.php` (tree and every added line of history on all refs), gitleaks v8.30.0 pinned by image digest (sha256:691af3c7...) run in Docker with the repository mounted read only and `--redact`.

## 4. Areas reviewed with no finding

- **Envelope v3 (src/Crypto/Envelope.php)**: AES-256-GCM through OpenSSL, 96-bit random nonce from `random_bytes` per call (an injectable nonce source is marked @internal), 16-byte tag, canonical base64 required (no malleable second spelling), context is mandatory AAD (ciphertext cannot move between records), `kid` pattern validated, size cap 32 MiB, failed decryption returns nothing, `rewrap` verifies before returning. KeyRing refuses low-entropy keys; KeyFile writes with `tempnam` (0600) then chmod then rename and inspects mode and web root; KeyGenerator uses only `random_bytes`; KeyPurpose derives subkeys with HKDF. VaultKeyWrap: Argon2id (65536 KiB, 3 ops) or PBKDF2 600000, parameters read from a stored wrap are bounded both ways (MIN and MAX constants), salt 16 random bytes, header bound into the AAD. Legacy readers (ENC, ENC2, enc, vault CBC, V1/V2) are read-only, selected by prefix; `PlaintextPassthroughReader` is opt-in and excludes every known prefix. No custom crypto.
- **Comparisons**: no `==`, `===` or `strcmp` on a token, secret, hash or signature in src/; every check is `hash_equals` or a lookup on a SHA-256 hash. Token entropy: enrollment 6+20 bytes, device 32, hosted grant 24, transfer 32 bytes, all `random_bytes`; no `rand`, `mt_rand`, `uniqid`; `md5`/`sha1` only for cache keys and bucket names.
- **Enrollment tokens**: selector (12 hex) plus 160-bit secret, SHA-256 stored (acceptable for high entropy), unknown selector and wrong secret return the identical `invalid_token`; `max_uses` is a conditional UPDATE in the placement transaction and rolls back with a failed enrollment (parallel requests cannot exceed it); `rvte1.` / `rvtp1.` / `rvpd_` kinds are separated everywhere.
- **Check-in and signing**: idempotent per (device, seq) under `FOR UPDATE`, token hash and revoked state re-verified inside the transaction, +900 s future bound, body capped. Ed25519 through libsodium; verification checks key and signature lengths; canonical JSON rejects ambiguity; the agent verifies signature before expiry, issued-at skew, device scope and type, persists the job id before launch, and the update path verifies the manifest signature before trusting the hash (key pinned at enrollment, downgrade impossible because the self-test binds the binary's own version).
- **Request parsing**: all JSON bodies read at most max+1 bytes, depth 512 (16 for Panel), non-list objects only; uploads and transfers capped, hash-checked, random storage names; downloads allow-list file names; pagination clamped.
- **SQL**: about 120 string-built sites traced; all fragments come from constants, `match` arms or clamped integers; no second-order splicing; LIKE escaping on both engines; PostgreSQL DSN values are strict allow-lists (no option injection), emulated prepares off, `PdoErrorMapper` returns a capped primary message with no parameters; a wrong-password exception trace did not contain the password. `RmmStoreMigrator` is DB-scoped locked, resumable, copies history tables only and never touches sealed columns; `CircuitBreakerConnection` state file is 0600, atomic, owner-checked.
- **Redis**: Lua scripts are constants and keys travel as RESP arguments (no key injection), `clear` uses an allow-list with `SCAN` (no `KEYS`), TLS sets verify_peer and verify_peer_name together, host/username/password validated with `\z`, `RedisAdmin::test` messages are fixed strings. Fail-open on lock, limiter and token bucket is the documented design (threat model section 5).
- **SSRF** other than CORE-01: redirects never followed, protocols limited, proxy bypassed when pinned, response capture capped, IPv6 forms and numeric hosts covered by the earlier battery plus mapped/NAT64/6to4/Teredo/zone ids re-run.
- **assets/ui JavaScript**: every `innerHTML` is static strings or `esc()`-escaped; the webhook wizard rebuilds guide HTML from an allow-list with URL protocol checks; no `eval`, `document.write`, `postMessage`, or jQuery `.html()`; storage holds only destination ids and a toggle. Info: edition-supplied guide HTML may carry arbitrary `class` values (restyle only).
- **Go agent**: no `InsecureSkipVerify` except the pinned Mesh client (pin enforced in VerifyConnection) and the explicit signed-check opt-out, TLS 1.2 minimum; scripts run from a 0700 temp file never via `sh -c`; parameters travel as environment variables; software deploy validates every parameter, https DNS names only, re-hashes before exec; credentials stored 0600/DPAPI; `go.mod` requires only `golang.org/x/sys`, so every regular expression is RE2 (linear).
- **Scripts and shell**: shellcheck `-S warning` only reports SC2155 in winres/gen.sh and template-placeholder notes in uptime-linux.sh; `install-linux.sh` uses a private mktemp directory, HTTPS-only fetch, SHA-256 for `--url` downloads; build-host token in a 0600 curl config (never argv); containers run with cap-drop, read-only root and resource limits; `install-ui-assets` / `promote-ui-assets` refuse symlinks and replace by rename.
- **Dependencies**: `composer audit --locked` reports no advisories (see section 5 for the run). Dockerfile has one `FROM`, pinned by digest. Actions are pinned by commit SHA and permissions are read-only at top level with `contents: write` only in `release`; no `pull_request_target` or `workflow_run`.
- **Prior reviews (REVIEW_RC30, REVIEW_RC36, review-2026-10)**: spot-verified that the fixes still hold (anchors `\z` in the SR-01/02 sites, SR-04 response cap, SR-05 metadata truncation, rc.38 M1 to M3 limits, L6 client_invalid, L11 installer symlink refusal, RC30 F5 upload gate, F9 `run_and_clean`). Regression: the SR-02 class (a `$` anchor without `D`) is still present in about 60 protocol patterns (CORE-10) and the RC36 L1 name rules never reached the job-output redactor (CORE-06c, CORE-18). The Redis password serialisation case documented by the WIP test of 2026-10-06 was still true (CORE-07).
