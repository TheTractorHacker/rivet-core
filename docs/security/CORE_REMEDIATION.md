## Open items (not fixed in Core)

* **CORE-05 reinstall takeover.** The reinstall-by-serial/machine_guid rule is documented and frozen in docs/rmm/PROTOCOL.md; changing it alters the device protocol outcome. Mitigations available today: short-TTL, low `max_uses` enrollment tokens; revoke tokens after rollout. Proposed additive change for a later rc, off by default: a setting `reinstall_requires_approval_when_online` that sets `link_state=pending_approval` and `match_reason=reinstall_while_online` when the stored device checked in within `offline_after_s`, plus no job offers to non-linked devices. Decision for Blake.
* **CORE-13 Windows state directory ownership.** Not testable here (no Windows runner). Proposed fix for `endpoint-agent/internal/store/perm_windows.go` and `scripts/install-windows.ps1`: after `MkdirAll`, read the owner with `GetNamedSecurityInfo(OWNER_SECURITY_INFORMATION)`; if it is not SYSTEM (S-1-5-18) or Administrators (S-1-5-32-544), or the directory is a reparse point, re-own it with `SetNamedSecurityInfo` (take ownership as SYSTEM) before applying the protected DACL, or refuse to start; create each missing parent with an explicit descriptor (owner SYSTEM, DACL SYSTEM+Administrators) instead of `MkdirAll`. Test on a Windows runner: pre-create `C:\ProgramData\RivetIT` as a standard user, install, assert the owner and that the user can no longer write `config.json`. Cross-compile check: `GOOS=windows go vet ./...`.
* **CORE-18 Go job and log redaction parity.** Port the new PHP name rules to `endpoint-agent/internal/jobs/redact.go` and add shared vectors (`agent_job_redaction_vectors`, new file, not an edit of a frozen one) that both languages must pass.
* Release provenance (INFO-09): add `actions/attest-build-provenance` pinned by commit SHA with `id-token: write` and `attestations: write` on the release job, and publish a detached signature of SHA256SUMS. Not done: it cannot be tested without a release run.
* INFO-03 to INFO-08: accepted, reasons in the audit.
