<a id="n8n"></a>
### n8n

Workflow automation (fair-code, self-hostable). Start a workflow from a Webhook node.

- Preset id: `n8n`
- Body format: `json`, method `POST`
- URL: `https://n8n.example.com/webhook/<path>`
- Authentication: none, **hmac**, header, bearer, basic
- Vendor docs: <https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/>

Setup:

1. In n8n create a workflow and add a Webhook node as the trigger.
2. Set HTTP Method to POST (the default is GET) and choose a Path.
3. Copy the Production URL (it contains /webhook/, not /webhook-test/) and paste it here.
4. Optionally set Authentication on the node (Basic or Header) and mirror it in the Authentication section here.
5. To verify our signature, enable the node option Raw Body, then use the Code-node snippet below.
6. Activate the workflow. The Test URL (/webhook-test/) only works while you click "Listen for test event".

Test from a shell:

```bash
curl -sS -X POST 'https://n8n.example.com/webhook/<path>' \
  -H 'Content-Type: application/json' \
  --data-binary '{"event":"ticket.created","timestamp":"2026-01-02T03:04:05Z","data":{"ticket_id":1042,"ticket_number":"TCK-1042","ticket_subject":"Printer on floor 2 is offline","ticket_priority":"High","ticket_status":"Open","client_id":7,"client_name":"Acme Corp","contact_id":31,"contact_name":"Dana Reyes","assigned_to_user_id":4,"assigned_to_user_name":"Sam Technician"}}'
```

Things to know:

- Production URLs only work while the workflow is Active; the /webhook-test/ URL only accepts one call after you click "Listen for test event".
- Our JSON arrives under $json.body, headers under $json.headers.
- n8n parses JSON before your Code node runs; verifying the signature needs the Raw Body option, and the Code node needs NODE_FUNCTION_ALLOW_BUILTIN=crypto. Verify against the n8n docs for your version.
- n8n is "fair-code" (Sustainable Use License): source-available and free to self-host, not OSI open source.
- If the platform runs on your own LAN, add its network under Settings > Webhooks > Internal networks first; private addresses are blocked by default.

Verifying our signature: this platform can check `X-Rivet-Signature-V2`; see the snippets in [webhooks.md](webhooks.md#verifying-a-signature).

<a id="node-red"></a>
### Node-RED

Flow-based programming (open source). Receive the call with an "http in" node.

- Preset id: `node-red`
- Body format: `json`, method `POST`
- URL: `https://nodered.example.com/<path>`
- Authentication: none, **hmac**, basic, bearer, header
- Vendor docs: <https://nodered.org/docs/user-guide/nodes>

Setup:

1. Add an "http in" node, set Method to POST and a URL such as /rivet.
2. Connect it to your flow and finish with an "http response" node (status 200); without it the sender waits until it times out.
3. Deploy, then paste the full URL (https://<host>/rivet) here.
4. Protect the endpoint: set httpNodeAuth in settings.js (basic) or check a header in a function node, and configure the same under Authentication here.
5. Our JSON body is in msg.payload; headers are in msg.req.headers.

Test from a shell:

```bash
curl -sS -X POST 'https://nodered.example.com/<path>' \
  -H 'Content-Type: application/json' \
  --data-binary '{"event":"ticket.created","timestamp":"2026-01-02T03:04:05Z","data":{"ticket_id":1042,"ticket_number":"TCK-1042","ticket_subject":"Printer on floor 2 is offline","ticket_priority":"High","ticket_status":"Open","client_id":7,"client_name":"Acme Corp","contact_id":31,"contact_name":"Dana Reyes","assigned_to_user_id":4,"assigned_to_user_name":"Sam Technician"}}'
```

Things to know:

- Without an "http response" node Node-RED never answers and our attempt is logged as a timeout.
- The HTTP-in node does not keep the raw request body by default, so re-serialising msg.payload can differ from the signed bytes. Verify against the Node-RED docs for capturing the raw body before relying on signature checks.
- Node-RED is normally on a LAN or behind a reverse proxy; allow the network under Internal networks if needed.

Verifying our signature: this platform can check `X-Rivet-Signature-V2`; see the snippets in [webhooks.md](webhooks.md#verifying-a-signature).

<a id="windmill"></a>
### Windmill

Open-source (AGPL) scripts, flows and apps. Trigger a script or flow by its webhook endpoint.

- Preset id: `windmill`
- Body format: `json`, method `POST`
- URL: `https://windmill.example.com/api/w/<workspace>/jobs/run/p/<script-path>`
- Authentication: **bearer**, header
- Vendor docs: <https://www.windmill.dev/docs/core_concepts/webhooks>

Setup:

1. In Windmill open the script or flow and choose Triggers > Webhooks (or copy the URL pattern above).
2. Create a user token (Account settings > Tokens) and enter it here under Authentication > Bearer.
3. Make the script accept the arguments event (string), timestamp (string) and data (object); Windmill maps JSON body keys to script arguments by name.
4. Paste the run-by-path URL (jobs/run/p/...) here. Use jobs/run_wait_result/p/... only if you need the result; the default is asynchronous.

Test from a shell:

```bash
curl -sS -X POST 'https://windmill.example.com/api/w/<workspace>/jobs/run/p/<script-path>' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <token>' \
  --data-binary '{"event":"ticket.created","timestamp":"2026-01-02T03:04:05Z","data":{"ticket_id":1042,"ticket_number":"TCK-1042","ticket_subject":"Printer on floor 2 is offline","ticket_priority":"High","ticket_status":"Open","client_id":7,"client_name":"Acme Corp","contact_id":31,"contact_name":"Dana Reyes","assigned_to_user_id":4,"assigned_to_user_name":"Sam Technician"}}'
```

Things to know:

- Windmill maps JSON keys to script arguments: a script without event/timestamp/data parameters will reject the call. Verify against the Windmill docs for your version.
- A bearer token is required; webhooks also accept a token query parameter, but a header keeps it out of logs.
- If the platform runs on your own LAN, add its network under Settings > Webhooks > Internal networks first; private addresses are blocked by default.

Verifying our signature: this platform can check `X-Rivet-Signature-V2`; see the snippets in [webhooks.md](webhooks.md#verifying-a-signature).

<a id="huginn"></a>
### Huginn

Open-source (MIT) agents that watch and act. Receive events with a Webhook Agent.

- Preset id: `huginn`
- Body format: `json`, method `POST`
- URL: `https://huginn.example.com/users/{user_id}/web_requests/{agent_id}/{secret}`
- Authentication: **none**, hmac
- Vendor docs: <https://github.com/huginn/huginn/wiki/Agent-Webhook-Agent>

Extra fields:

- `user_id` (text, required): The number in the URL Huginn shows for the agent.
- `agent_id` (text, required): The Webhook Agent id.
- `secret` (secret, required): The "secret" option of the Webhook Agent.

Setup:

1. Create a Webhook Agent. Set "secret" to a long random value and "verbs" to include post.
2. Set expected_receive_period_in_days (required; Huginn flags the agent as stale otherwise).
3. The agent URL is https://<huginn>/users/<user_id>/web_requests/<agent_id>/<secret>; enter its three parts here.
4. Add an agent that consumes the events (for example a Trigger Agent filtering on event).

Test from a shell:

```bash
curl -sS -X POST 'https://huginn.example.com/users/{user_id}/web_requests/{agent_id}/{secret}' \
  -H 'Content-Type: application/json' \
  --data-binary '{"event":"ticket.created","timestamp":"2026-01-02T03:04:05Z","data":{"ticket_id":1042,"ticket_number":"TCK-1042","ticket_subject":"Printer on floor 2 is offline","ticket_priority":"High","ticket_status":"Open","client_id":7,"client_name":"Acme Corp","contact_id":31,"contact_name":"Dana Reyes","assigned_to_user_id":4,"assigned_to_user_name":"Sam Technician"}}'
```

Things to know:

- Huginn authenticates by the secret in the URL path only; there is no header authentication, so use HTTPS.
- By default only the verbs listed in the agent options are accepted: make sure post is included. Verify against the agent's built-in description.
- The JSON body becomes the event payload (see the agent's payload_path option).

Signature verification: not available on this platform; the URL (or token) is the secret.

### IFTTT Webhooks

Trigger an applet with the Webhooks service (event name + key).

- Preset id: `ifttt`
- Body format: `template`, method `POST`
- URL: `https://maker.ifttt.com/trigger/<event>/with/key/<key>`
- Saved URL must match: `#^https://maker\.ifttt\.com/trigger/[A-Za-z0-9_-]+/(?:with/key|json/with/key)/[A-Za-z0-9_-]+/?$#`
- Authentication: **none**
- Vendor docs: <https://ifttt.com/maker_webhooks>

Setup:

1. Connect the Webhooks service in IFTTT and open its Documentation page to find your key.
2. Create an applet: If "Receive a web request" with an event name, Then your action.
3. URL: https://maker.ifttt.com/trigger/<event>/with/key/<key>; paste it here.
4. Use value1, value2 and value3 in the action; we fill them with title, summary and link.

Test from a shell:

```bash
curl -sS -X POST 'https://maker.ifttt.com/trigger/<event>/with/key/<key>' \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary '{"value1":"New ticket","value2":"TCK-1042 Printer on floor 2 is offline","value3":"https://helpdesk.example.com/ticket/1042"}'
```

Things to know:

- The URL is the secret: anyone who has it can post to the destination. It is stored encrypted and never shown again.
- IFTTT only passes three values (value1, value2, value3) to the action; we send title, summary and link. Use /json/with/key/ in the URL and the Generic JSON destination to send the whole envelope instead.
- Free accounts are limited to a small number of applets; verify against the IFTTT pricing and docs.

Signature verification: not available on this platform; the URL (or token) is the secret.

4. Untick "Only accessible from the local network" unless the sender is on the same network (default is local only).

curl -sS -X POST 'https://homeassistant.example.com/api/webhook/<webhook_id>' \

Things to know:

- The webhook ID is the only secret; use a long random one and HTTPS (Nabu Casa or your reverse proxy).
- The trigger option "local_only" defaults to true: requests from other networks are rejected. Home Assistant normally sits on a private LAN, so you also need it under Internal networks here.
- JSON bodies are available as trigger.json, form bodies as trigger.data.

Signature verification: not available on this platform; the URL (or token) is the secret.

## Push and notification services

<a id="apprise"></a>
### Apprise API

Open-source (BSD) notification gateway that fans out to 100+ services.

- Preset id: `apprise`
- Body format: `apprise`, method `POST`
- URL: `https://apprise.example.com/notify/{key}`
- Authentication: **none**, hmac, basic, bearer, header
- Vendor docs: <https://github.com/caronc/apprise-api>

Extra fields:

- `key` (text, required): The key of a saved Apprise configuration (stateful mode).
- `tag` (text, optional): Only notify the services with this tag (comma separated for OR).

Setup:

1. Run the Apprise API container and open its web UI.
2. Create a configuration with your service URLs (Slack, e-mail, Telegram, ...) and note its key.
3. Use https://<apprise>/notify/<key> as the URL; set a tag to target some of the services.
4. Apprise API has no authentication of its own: put it behind a reverse proxy with basic auth and set the same under Authentication.

Test from a shell:

```bash
curl -sS -X POST 'https://apprise.example.com/notify/{key}' \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary '{"title":"New ticket","body":"TCK-1042 Printer on floor 2 is offline\nPriority: High\nClient: Acme Corp\nStatus: Open\nAssigned to: Sam Technician\nContact: Dana Reyes\nhttps://helpdesk.example.com/ticket/1042","type":"warning","format":"text"}'
```

Things to know:

- We send {title, body, type, format:"text"} to /notify/<key>. type maps severity to info, warning or failure.
- Apprise API itself is unauthenticated by default; do not expose it to the internet without a proxy.
- If the platform runs on your own LAN, add its network under Settings > Webhooks > Internal networks first; private addresses are blocked by default.

Signature verification: not available on this platform; the URL (or token) is the secret.

<a id="ntfy"></a>
### ntfy

Open-source (Apache/GPL) push notifications to phone and desktop. Public ntfy.sh or self-hosted.

- Preset id: `ntfy`
- Body format: `ntfy`, method `POST`
- URL: `https://ntfy.sh/{topic}`
- Authentication: **none**, bearer, basic
- Vendor docs: <https://docs.ntfy.sh/publish/>

Extra fields:

- `topic` (text, required): Anyone who knows a topic name on a public server can read it: use a long random name or access control.
- `priority` (number, optional): Leave empty to derive it from severity (3 info, 4 warning, 5 critical).
- `tags` (text, optional): Comma-separated tags or emoji short codes added to every message.

Setup:

1. Choose a topic name (long and random on the public server) and subscribe to it in the ntfy app.
2. URL: https://ntfy.sh/<topic>, or your self-hosted server.
3. For a protected topic create an access token (ntfy token add) and enter it under Authentication > Bearer.
4. Send a test; the message title, priority and tags come from the event.

Test from a shell:

```bash
curl -sS -X POST 'https://ntfy.sh/{topic}' \
  -H 'Content-Type: text/plain; charset=utf-8' \
  -H 'Title: New ticket' \
  -H 'Priority: 4' \
  -H 'Tags: warning' \
  -H 'Click: https://helpdesk.example.com/ticket/1042' \
  --data-binary 'TCK-1042 Printer on floor 2 is offline
Priority: High
Client: Acme Corp
Status: Open
Assigned to: Sam Technician
Contact: Dana Reyes'
```

Things to know:

- The body is the message text; Title, Priority, Tags and Click are sent as headers. Non-ASCII titles are sent as RFC 2047 encoded words; verify against the ntfy docs for your server version.
- The message limit is 4096 bytes; we truncate.
- ntfy.sh rate-limits publishers per IP (defaults are a burst of about 60 requests, then roughly one per 5 seconds); self-hosted limits are configurable. Verify against the ntfy docs.
- A public topic name is effectively a password.

Signature verification: not available on this platform; the URL (or token) is the secret.
