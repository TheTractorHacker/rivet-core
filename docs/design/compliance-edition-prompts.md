# Customizable compliance frameworks: ready-to-paste prompts for the editions (phase 4 of #92)

Phases 1 and 2 (RivetCore 1.0.0-rc.44, migration 0046) ship the services: profiles, the checks, retention enforcement, restore-test evidence and the `BackupFactsProviderInterface`. Each edition now needs the settings page, the real backup facts, the PostgreSQL store in the real backup, a scheduled restore test, and the wiring. Paste one prompt into the chat of the edition (BETA ONLY). Design: [compliance-frameworks.md](compliance-frameworks.md). Adoption steps: UPGRADING.md "Adopting customizable compliance frameworks". The editions already have the pieces these prompts build on (`src/Recovery/BackupStatus.php` and the `backup_runs` table, `deploy/backup.sh` with `--offsite`, `cron/restore_drill.php` and `restore_drill_log`, the compliance pages); the prompts say to read them first and to extend them additively.

Checklist of #92 after phases 1 and 2 (tick as the editions land):

- [x] Phase 1: design, data model, migration 0046, profile store, built-ins, import and export (rc.44)
- [x] Phase 2: requirement types and checks, edition facts interface, retention enforcement, restore-test evidence (rc.44)
- [ ] Phase 3 (Core): integrity chain for hot data (replaces the `IntegrityChainCheck` placeholder), time-to-availability
- [ ] Phase 4 RivetIT beta: settings page, facts provider, PostgreSQL in the backup and the off-site copy, scheduled restore test, report
- [ ] Phase 4 RivetMSP beta: same
- [ ] Production rollout of each edition after beta (separate decision)
