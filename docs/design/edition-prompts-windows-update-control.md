# Edition prompts: RivetCore 1.0.0-rc.65 (patch policy: manage Windows Update, hold the feature version; no migration)

Core added Windows Update control (issue #126). Read `docs/rmm/PATCHING.md` section 12 and the rc.65 CHANGELOG entry first. **No migration**: the three new settings live in `rmm_patch_policies.settings_json`, the reported state in one durable row per device in `rmm_patch_jobs`. **The registry writes have not been run on Windows yet** (`docs/rmm/WINDOWS_UPDATE_CONTROL_TEST.md` is the plan): the UI must not promise more than the text below, and nothing here may be switched on for a customer fleet before that plan has been run.

What Core does, so the prompts can stay short:

- Three patch policy settings (all optional, defaults touch nothing): `windows_update_mode` (`leave` | `managed`), `windows_feature_target` (`none` | `hold` | a version matching `^[0-9]{2}H[12]$`, e.g. `24H2`, `25H2`, `26H2`) and `windows_quality_defer_days` (0 to 30). They go through the existing patch policy save (`PatchActions::savePolicy`, REST `patch_policies`) inside `settings`. Saving any of them needs `rmm.patch.install` on top of the policy write rights; without it the save returns 403 with a plain message the page shows as is.
- `GET endpoint_devices/{id}/patches` returns `summary.windows_update` (null for a device that is not Windows) with `status` (`off`, `in_sync`, `pending`, `restore_pending`, `externally_managed`, `not_reported`, `unsupported_agent`, `automation_disabled`), `capable`, `reported_at`, `feature_version`, `build`, `product`, `target_version`, `newer_than_target`, `external` (list of `wsus`, `gpo`, `mdm`, `changed_since`), `policy`, `core_keys`, `pending_changes`, `last_configure` (`outcome`, `mode`, `at`, `changes`, `detail`) and `summary.policy.windows` (`update_mode`, `feature_target`, `quality_defer_days`, `active`).
- `POST endpoint_devices/{id}/patches/configure` with `{"mode":"dry_run"}` (needs `rmm.patch.manage`) or `{"mode":"apply","confirm":true}` (needs `rmm.patch.install`) queues the policy's desired state on one device now; `200` with `skipped` says why nothing was queued; it stays a dry run while the instance's live installs limit is off.
- The alert check `patch.feature_version` opens when a Windows device runs a feature version newer than the one its policy holds it at.

Text the editions use (keep these words, they are the safe promise):

- Mode, short: **"Manage Windows Update"**. Explanation: *"Managed devices stop updating themselves. Windows only tells the user that updates exist; only the updates you approve are installed, by RivetIT, in the install window of the patch policy. Turn this on only for devices you actually patch with RivetIT."*
- Feature version, short: **"Windows version"** with the choices *Do not control*, *Stay on the version the device runs now (hold)* and *A specific version...* (a text box that accepts only `24H2` style values: two digits, H, 1 or 2). Explanation: *"Stops Windows from moving to a newer version by itself. A held or chosen version stays until you change it on purpose: nothing ever moves a device to the next Windows version automatically. When you want to move on, change the version here, test on a pilot group first, and expect the device to download and install that version."*
- Warning shown next to the field when a version or hold is chosen, and in the confirmation dialog: **"A held version must be moved deliberately. Devices will not receive the next Windows version, and will eventually run a version Microsoft no longer supports, until you raise or remove this setting."**
- Deferral: **"Delay quality updates by N days"** (0 to 30, 0 = no delay).
- The message for a machine something else manages (use verbatim, replacing `{who}`): *"Windows Update on this device is managed by {who}, so RivetIT leaves it alone and changed nothing. To let RivetIT control it, remove that setting first."* with `{who}` = *a WSUS server* (`wsus`), *a group policy* (`gpo`), *a mobile device management policy such as Intune* (`mdm`), *another tool that changed a setting RivetIT had made* (`changed_since`).
- A device that has not announced the capability: *"This device's agent is too old to control Windows Update. Update the agent first."* A device marked managed by another RMM: *"This device is marked as managed by another RMM; RivetIT does not change Windows Update on it."*
